# Go-SyncFlow - 系统使用手册

> 版本：v3.6 | 更新日期：2026-03-14

本文档面向系统管理员，描述 Go-SyncFlow 统一身份管理平台的各功能模块操作指南。

---

## 1. 系统概述

Go-SyncFlow 是一套企业级统一身份管理平台，提供以下核心功能：

- **用户管理**：用户、角色、权限的集中管理
- **同步管理**：支持多种数据源的双向同步（含用户、群组、角色）
- **单点登录**：支持 CAS、SAML、OIDC 协议
- **VPN 接入**：集成 VPN 用户认证与管理
- **安全中心**：登录安全、IP 管控、告警通知
- **实时监控**：WebSocket 实时数据推送，仪表盘动态刷新

## 3. 用户管理

### 3.1 用户列表

**路径**：用户管理 → 用户列表

**功能**：
- 查看所有系统用户
- 支持按用户名、姓名、手机号搜索
- 支持按状态、角色、分组筛选
- 支持批量操作
- **实时刷新**：用户数据变更时自动更新列表

**操作**：
1. 点击「新建用户」创建用户
2. 点击用户行可查看/编辑详情
3. 状态开关可快速启用/禁用用户
4. 点击「重置密码」可重置用户密码

### 3.2 创建用户

**必填项**：
- 用户名（登录账号，唯一）
- 显示名称

**可选项**：
- 邮箱、手机号
- 所属分组
- 所属角色
- 密码（不填则自动生成）

**下游同步**：创建用户后，系统会自动触发下游同步，将用户同步到已配置的下游系统（AD、LDAP、数据库等）。

### 3.3 用户状态

| 状态 | 说明 | 下游同步行为 |
|------|------|-------------|
| 正常 | 可正常登录使用 | 同步到下游，启用状态 |
| 禁用 | 无法登录，保留数据 | 同步到下游，禁用状态（AD 设置 userAccountControl） |

### 3.4 用户分组

用户分组采用树形层级结构，支持多级嵌套。分组变更会自动同步到下游系统：

- **AD 下游**：分组映射为 OU（组织单位），用户移动到对应 OU
- **LDAP 下游**：分组映射为 OU 或 groupOfNames
- **数据库下游**：分组写入配置的分组表

**分组删除处理**：
- 删除分组时，该分组下的用户会自动移动到父级分组
- 下游 AD 的 OU 也会相应删除，用户移动到父级 OU

### 3.5 批量操作

- 批量启用/禁用
- 批量重置密码
- 批量分配角色
- 批量移动分组
- 导出用户列表（Excel）

## 5. 同步管理

### 5.1 上游同步

**路径**：同步管理 → 上游同步

**功能**：从外部数据源同步用户和分组到本系统

**支持的连接器**：

| 类型 | 名称 | 说明 |
|------|------|------|
| im_dingtalk | 钉钉 DingTalk | 从钉钉组织架构同步用户和部门 |
| im_wechatwork | 企业微信 WeChatWork | 从企业微信通讯录同步用户和部门 |
| im_feishu | 飞书 FeiShu | 从飞书组织架构同步用户和部门 |
| im_welink | WeLink | 从华为 WeLink 同步用户 |
| ldap_ad | Active Directory | 从 AD 域控同步用户和分组 |
| ldap_generic | 通用 LDAP | 从 OpenLDAP 等服务器同步用户和分组 |
| db_mysql | MySQL | 从 MySQL 数据库同步用户和分组 |
| db_postgresql | PostgreSQL | 从 PostgreSQL 数据库同步用户和分组 |
| db_oracle | Oracle | 从 Oracle 数据库同步用户和分组 |
| db_sqlserver | SQL Server | 从 SQL Server 数据库同步用户和分组 |
| http_api | HTTP API | 通过自定义 HTTP 接口同步用户和分组 |
| radius | RADIUS 服务器 | 通过 RADIUS 协议认证用户 |

**配置步骤**：
1. 新建上游连接器，填写连接参数
2. 点击「测试连接」验证
3. 新建同步规则，选择连接器
4. 配置字段映射
5. 设置同步触发方式（定时/手动）

**上游删除处理**：
- 当上游用户被删除时，本地用户会被禁用（不直接删除）
- 当上游分组被删除时，本地分组会被删除，用户移动到父级分组
- 这些变更会自动触发下游同步

### 5.2 下游同步

**路径**：同步管理 → 下游同步

**功能**：将本系统用户、分组、角色同步到外部系统

**支持的连接器**：

| 类型 | 名称 | 用户同步 | 分组同步 | 角色同步 |
|------|------|---------|---------|---------|
| ldap_ad | Active Directory | ✓ | ✓ (OU) | ✓ (安全组) |
| ldap_generic | 通用 LDAP | ✓ | ✓ (OU/groupOfNames) | ✓ (groupOfNames) |
| db_mysql | MySQL | ✓ | ✓ | ✓ |
| db_postgresql | PostgreSQL | ✓ | ✓ | ✓ |
| db_oracle | Oracle | ✓ | ✓ | ✓ |
| db_sqlserver | SQL Server | ✓ | ✓ | ✓ |

**事件触发同步**：

| 事件 | 说明 |
|------|------|
| user_create | 用户创建 |
| user_update | 用户更新（含分组移动） |
| user_delete | 用户删除 |
| user_enable | 用户启用 |
| user_disable | 用户禁用 |
| password_change | 密码变更（含密码学习） |
| role_change | 用户角色变更 |
| group_create | 分组创建 |
| group_update | 分组更新（含重命名、移动） |
| group_delete | 分组删除 |
| role_create | 角色创建 |
| role_update | 角色更新 |
| role_delete | 角色删除 |

**AD 下游特殊处理**：
- OU 层级创建：严格按照本地分组层级创建 OU，先父后子
- OU 删除：先将 OU 内的用户和子 OU 移动到父级，再删除空 OU
- 用户状态映射：`status` 字段通过 `status_to_uac` 转换为 `userAccountControl`

### 5.3 字段映射

配置源字段与目标字段的对应关系：

```
示例：
源字段 displayName → 目标字段 cn
源字段 email → 目标字段 mail
源字段 phone → 目标字段 telephoneNumber
```

**转换规则**：
- `{{value}}`：直接使用原值
- `{{value | lower}}`：转小写
- `{{value | upper}}`：转大写
- `固定值`：直接填写固定值

**密码格式转换**（PasswordFormat）：

| 格式 | 说明 | 适用场景 |
|------|------|----------|
| plaintext | 明文 | 测试环境 |
| bcrypt | bcrypt 哈希 | 通用 Web 系统 |
| bcrypt_sha256 | bcrypt(SHA256(密码)) | 本系统默认格式 |
| sha256 | SHA256 哈希 | 简单数据库 |
| sha512 | SHA512 哈希 | 高安全性数据库 |
| md5 | MD5 哈希 | 旧系统兼容 |
| ssha | LDAP SSHA 格式 | OpenLDAP |
| nt_hash | NT Hash (MD4) | AD / Samba |
| argon2id | Argon2id 哈希 | 高安全性系统 |
| scram-sha-256 | SCRAM-SHA-256 | PostgreSQL |
| unicode_pwd | UTF-16LE 编码 | AD unicodePwd 属性 |

### 5.4 同步日志

**路径**：日志管理 → 同步日志

**功能**：
- 查看所有同步记录
- 按方向（上游/下游）、触发方式、状态筛选
- **实时刷新**：新同步日志自动显示

**字段说明**：

| 字段 | 说明 |
|------|------|
| 方向 | 上游/下游 |
| 触发 | 事件/定时/手动 |
| 事件 | 触发的具体事件类型 |
| 状态 | 成功/部分成功/失败 |
| 概要 | 同步结果摘要 |

### 10.5 密码代理

**路径**：系统设置 → 密码代理

**功能**：代理用户密码认证到外部系统，学习用户密码

**支持的认证源**：

| 类型 | 说明 |
|------|------|
| LDAP（AD/OpenLDAP） | 通过 LDAP 协议认证并学习密码 |
| 数据库 | 通过数据库查询认证并学习密码 |
| RADIUS | 通过 RADIUS 协议认证并学习密码 |
| HTTP API | 通过自定义 HTTP 接口认证并学习密码 |

**应用场景**：
- IM平台用户（钉钉/飞书/企微）无密码，通过代理认证学习密码
- 上游同步的用户通过代理认证学习密码
- 用户首次登录从旧系统迁移密码

**密码学习触发场景**：

| 场景 | 说明 |
|------|------|
| Web 登录代理 | 用户通过 Web 界面登录，本地无密码时代理到上游认证 |
| 本机 LDAP 服务 | 外部系统通过本机 LDAP Bind 认证，触发密码代理 |
| VPN 认证 | VPN 用户认证时，代理到配置的认证源 |
| API Key 认证 | 通过 HTTP API 认证用户 |

**密码学习机制**：
当用户本地无密码或密码验证失败时，系统会尝试通过配置的上游连接器进行密码代理认证。认证成功后：
- 本地密码更新为 `bcrypt(SHA256(明文密码))` 格式
- 同时生成 `SambaNTPassword` 以支持本地 LDAP 服务
- 触发 `password_change` 事件，同步密码到下游系统
- 后续登录将直接使用本地密码验证

**密码下游同步**：
密码变更（包括学习）后，系统会根据配置的属性映射和密码格式，将密码同步到下游：
- **AD 下游**：通过 `unicodePwd` 属性设置（需 LDAPS）
- **LDAP 下游**：通过 `userPassword` 属性设置（支持 SSHA 等格式）
- **数据库下游**：写入配置的密码字段（支持多种哈希格式）

> **注意**：上游同步不直接同步密码，密码统一通过密码代理功能学习。这样设计更安全且逻辑更清晰。

## 11. 仪表盘

### 11.1 首页仪表盘

**路径**：首页

**功能**：
- 系统状态概览
- 用户统计
- 同步状态
- 连接器状态
- 最近登录记录

**实时更新**：
仪表盘数据通过 WebSocket 实时推送更新，无需手动刷新。包括：
- 系统指标（CPU、内存、磁盘）
- 业务统计（用户数、角色数、连接器数）
- 同步状态变更
- 用户/分组/角色变更

**降级方案**：
当 WebSocket 连接不可用时（如通过反向代理且未配置 WebSocket），系统会自动切换到 HTTP 轮询模式，每 30 秒更新一次数据。

## 12. 常见问题

### 12.1 忘记管理员密码

1. 登录服务器
2. 使用重置脚本：
```bash
cd /opt/Go-SyncFlow
./scripts/reset-admin.sh
```

### 12.2 同步失败排查

1. 检查连接器配置是否正确
2. 点击「测试连接」验证
3. 查看同步日志中的错误详情
4. 检查网络连通性
5. 对于 AD 下游，检查 OU 层级是否存在

### 12.3 AD 同步用户数量不一致

可能原因：
1. 部分用户被禁用，未同步到 AD（检查 `status_to_delete` 规则）
2. OU 创建失败导致用户创建失败
3. 用户属性缺失必填字段

排查方法：
1. 查看同步日志，筛选失败记录
2. 检查属性映射配置
3. 确认 AD 连接器有足够权限

### 12.4 SSO 登录失败

1. 确认应用协议已启用
2. 检查 service/redirect_uri 白名单
3. 查看 SSO 登录日志
4. 确认账号在本系统存在

### 12.5 VPN 无法连接

1. 检查 VPN 服务状态
2. 确认用户组认证配置
3. 检查用户是否在允许的用户组
4. 查看 VPN 日志

### 12.6 仪表盘显示离线

1. 检查浏览器控制台是否有 WebSocket 错误
2. 如使用反向代理，确保配置了 WebSocket 转发
3. 系统会自动降级为 HTTP 轮询，数据仍会更新

## 14. 部署与维护

### 14.1 一键部署

```bash
# 解压
tar -xzf go-syncflow-v3.6-xxxxxxxx.tar.gz -C /opt/

# 启动
cd /opt/Go-SyncFlow
chmod +x scripts/*.sh
./scripts/start.sh
```

### 14.2 常用命令

```bash
# 启动服务
./scripts/start.sh

# 停止服务
./scripts/stop.sh

# 重启服务
./scripts/restart.sh

# 重置管理员密码
./scripts/reset-admin.sh

# 切换到外部数据库
./scripts/enable-external-db.sh

# 查看服务状态
systemctl status go-syncflow

# 查看日志
journalctl -u go-syncflow -f
```

### 14.3 数据库

系统默认内置 PostgreSQL 数据库，开箱即用。如需使用外部数据库，运行：

```bash
./scripts/enable-external-db.sh
```

按提示配置外部 PostgreSQL 连接信息。
